# 平地跳跃可行性复核 · 2026-10-06

本轮范围：阅读当前源码、入口、模型和历史原始数据；运行现有定向测试；从原生数据提取飞行入口做离线核对。未启动新仿真、未修改控制实现、默认参数、MPC 或历史试验数据。本轮新增实跑 0 次、腾空 0 次、达标 0 次。

## 判断

五阶段计划可以作为开发顺序，第一、二阶段具备可复用的观测、执行器和模型基础，但受限接地标定入口及完整保护尚需实现。当前实现不能完成最终验收；现有证据也不足以承诺在全部限制下最终一定可达。

已经能明确解释一个反复失败的原因：原 velocity 的实际飞行入口不适合当前 60 ms 收腿轨迹及静止腿、近零机身角速度的落地终点。应先改变推地结束的状态，再规划飞行。增加空中反馈或修改落地增益无法让当前不可行的参考曲线成为可行曲线。

这是对当前状态和轨迹族的结论，不是整机目标不可达的证明。工程推进有依据；完整目标的物理可达性仍需第三阶段计算和实跑证据。

## 原始数据核对

数据来源：`velocity_clearance_landing_20261005_224308`。

现有同物理步几何审计结果：双轮净空 15.3368 cm；首触后倾 5.7394°；首触角速度 +0.569381 rad/s；缓冲压缩 11.1899 cm；质心、轮轴最大后退分别 28.3631、40.6826 cm。缓冲一项达到现有门槛，其余主要修复指标失败。

重新扫描原生输入：共 21,725 个物理帧；两轮有效 before-physics JointForceCmd 均为 0 帧；四腿关节各 17,625 个有效输入帧。无效输入中没有被补成有限零值。原速度轮模式因此不能用于完整六输入动力学门的验收。

提取控制器 FLIGHT 入口 4.297 s 的同物理步原生 q/v，并确认从该帧起五个连续接触帧均无接触：

| 量 | 本次离线提取/计算 |
| --- | --- |
| 左髋位置、速度 | +0.619199 rad、+8.198530 rad/s |
| 左膝位置、速度 | −0.849311 rad、−13.323214 rad/s |
| CAD 模型估计总角动量 H | 1.192585 N·m·s |
| CAD 模型质心高度、竖直速度 | 0.463521 m、2.053671 m/s |
| 当前飞行规划器结果 | 拒绝，`joint_curve_limit` |

这里是已进入飞行的真实边界样本，不声称它就是接触首次消失的精确离地帧。H 和质心量由现有 CAD 模型计算，仍需模型门核对。

两项独立限制说明该拒绝有物理依据：

1. 现有收腿目标约为髋 +0.027870、膝 −0.162375 rad。沿用髋速度/加速度 11 rad/s、450 rad/s²，膝 15 rad/s、500 rad/s²，在 60 ms 内，即使允许任意终点速度，髋最低只能到 +0.368736 rad，膝最高只能到 −0.751516 rad；两者都到不了目标。该界限尚未计入力矩和采样延迟，已足以排除当前 60 ms 目标。
2. 当前规划器以终点腿速、机身角速度为零，令两轮自转承接 H，计算轮速 `H/(2*0.006481)`。此样本需要约 92.006 rad/s，超过该规划器的 28.571 rad/s 限制。这排除了该终点设定，不能推广成所有允许非零腿速的落地都不可达。

现有测试中也有已在空中、腿已收好、H=0 的人工状态能够通过规划器。本轮复算该状态得到预测净空约 56.40 cm。它只证明规划器能接受某些人工飞行边界，完全没有证明机器人能从地面在限制内到达该边界。

## 当前实现中的具体缺口

### 1. P 轮伺服未拒绝非有限输入

`wheel_effort_velocity_servo.py` 的回调和计算只检查时间新鲜度，没有检查速度/目标的有限性。Python 的现有 `min/max` 限幅行为导致：NaN 线速度映射到两轮 +30 rad/s；NaN 测量轮速在新鲜标志为真时产生两轮 +10 Nm。已直接运行原文件的纯函数复现，没有使用硬件或仿真。

C++ `support_wheel_servo_effort` 会拒绝非有限值，实际 Python 执行器不会，二者失效语义不一致。现有四项 Python 测试全部通过，但没有覆盖 NaN/Inf。应在第一阶段解决并增加针对性测试。

### 2. 接管保护尚未覆盖所有调用路径

`run_state_thrust` 开头的 `!effort_mode_active_` 分支会请求切换、发布下蹲位置及旧轮控制命令，然后返回；它在 `velocity_capture_session_.update` 之前。因此接管后的模式丢失可以绕过会话的 ActuatorUnavailable 处理。轨迹初始化待配对分支也提前返回，应一起审查。

现有会话单元测试覆盖的是纯会话函数，不是所有控制器提前返回分支。最新实跑没有旧控制回退，仅证明那一次实际路径通过，不等于这些分支已覆盖。

### 3. allocator 仍可能接回旧控制

分配器未激活且不是 contact-hold 时，THRUST 会设置 `thrust_support_allocator_legacy_active_diag_` 并调用旧 PD/前馈发布路径。当前没有一条贯穿推地、协调减速、预期离地确认及故障退出的唯一输出所有权状态机。

求解器虽限制迭代并记录耗时，运行接入没有按控制截止时间拒绝过期解。历史正常求解耗时较短，不替代超时处理的覆盖。

### 4. 支撑模型的适用状态没有形成验收范围

历史实际输入响应曾在 160 个双支撑 THRUST 步通过；随后 allocator 候选的 235 个双支撑步失败，轮加速度误差 RMS 约 130 rad/s²。后来的时序诊断 103 步也失败。接触存在不等于理想无滑移滚动前提成立。

支撑求解器已加入左右髋差分加速度、相等法向载荷约束，但它们默认关闭，当前控制器没有设置这两个输入字段。历史离线核对消除了髋反向大力矩，尚未形成运行验证。

现有响应门在脚本中明确为各维绝对 RMS 与相对 RMS 同时通过，相对分母为 `max(真实响应 RMS,1)`。它目前只决定双支撑 THRUST 集合的集成结果；自由飞行结果被报告但不影响该 PASS。阶段二需要扩展到固定协议和独立验证记录，阶段四还要独立验证自由飞行适用性。

### 5. 当前飞行接入未实现计划要求的完整边界

`NativeCommandStateHistory` 已订阅记录，但未用于 `run_allocator_flight` 初始化；该路径仍取 joint/IMU 配对，并对最多 10 ms 差距的 COM 数据做传播。当前不是计划中的原生同物理步 q/v/轮速/姿态/H 初始化。

推地角动量目标仍为固定参数 −0.08，velocity capture 另使用 +0.08。飞行规划器设计门仍是 20 cm，没有 22 cm 预测余量；终点轮速由 H 设定，规划接口没有轮轴水平速度输入，因此没有显式联合首触滚动匹配。落地和保持仍交给已有恢复控制，规划器未联合证明 8 cm 缓冲和 ≤1 cm 后退。

## 为什么反复修改仍没有修好

历史已有明确进步：纠正 COM 上升与轮底净空混用、记录真正生效的物理步输入、修正浮点时钟误判、加入接管锁定、保留失败样本。这些工作可以继续使用。

但候选推进中，离线数学正确、局部响应通过和整条物理轨迹可行尚未连起来。推地留下高速腿和较大 H，空中轨迹被准入门拒绝；保护/模式切换又可能回到旧控制；轮执行器的采样、消息延迟和滑移改变模型响应。最终表现为未收腿、碰限位、后倾或大幅后退。继续同时修改这些阶段的增益，很难隔离原因。

## 对五阶段计划的执行建议

| 阶段 | 当前判断 | 必须先补齐的证据/实现 |
| --- | --- | --- |
| 完整输入 | 可执行，有已有组件 | allocator 关闭的 P 轮站立/标定入口；非有限输入处理；所有提前返回保护；六输入与发布时序配对 |
| 接地制动 | 可执行，但尚无合格包络 | 保留支撑的髋膝轮协调停机；低速递增固定协议；独立验证；全部失败减速样本保留 |
| 推地重做 | 核心工作，尚未验证 | 制动包络约束下求可飞行终点；接触/滑移适用门；输出所有权；由首触轨迹反推 H 和水平运动 |
| 飞行与首触 | 有规划器基础，当前接入不足 | 原生边界初始化；实际采样延迟；22 cm 设计余量；首触轮速、缓冲、姿态及后退联合验证 |
| 连续三跳 | 尚不能开展 | 全指标单跳通过后冻结；最后通过实际 README 入口连续三跳，并检查默认站立/自平衡回归 |

下一轮应只验证一个问题：在关闭 allocator 的有界 P 轮模式下，能否稳定支撑并取得六关节完整有效的物理步输入。通过后才进入受限制动协议，不通过时只修输入、模式及保护。不要填入一个正的减速度常数来解除当前保护。

现有制动检查仍是两个标量减速度代入 `|v|*延迟+v²/(2a)+余量`。它可以保留作保护结构，但不等于已实现构型、速度、接触和延迟限定的实测停止包络。阶段二需要真正替换这一适用范围。
