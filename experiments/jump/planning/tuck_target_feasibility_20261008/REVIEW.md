# TUCK有效收腿目标：只读可行性审查

2026-10-08。默认控制及landing_capture_gain=1.60保持。仅检查源码和上轮三个原配置B1/B2/B3的实际Gazebo数据；不使用延后EXTEND候选作默认证据。本轮新增实跑/腾空/达标均0，未改任何源码/参数/保护/阶段时序，未构建、提交、推送或新增诊断框架。

## 结论：不进入A/B

**当前工况下TUCK主要完成残余腿速制动，并未实现净收腿。仅修改一个腿长/高度目标无效；不能满足本轮“其他控制逻辑不变”的实施前提。** 反向运动保护将四关节终点退回入口，实际髋轴至轮轴距离在TUCK期间增加而非缩短。

原名义目标0.66m本身IK可达，关节端点不越界；但不经过保护直接要求60ms到达该目标，膝峰值加速度664–781rad/s²，超过现有500限制。其运动学最短5ms网格时长75–85ms，会延长TUCK并推迟原tuck_finished触发的EXTEND。时间总预算看起来有余量，但不等同执行/姿态/落地已验证。保持反向保护则任何有效缩腿膝目标都被挡住；本轮不擅自移除这条保护或改变动作时机。

## 1. 名义设计与实际作用

源码 `src/bbot_balance_controller/src/bbot_velocity_jump_controller.cpp:390–424` 注释设计0.66→0.69m收展腿；L_RETRACT_=0.66、L_TOUCH_=0.69。这里的target_z是机身离地目标高度，**不是髋轴到轮轴长度**。IK helper（3717–3761）明确先扣除kHipBodyVerticalOffset=0.07和wheel_radius=0.07，再计算腿平面向量长度。

当前实际TUCK不是完全不动：入速沿原方向继续运动，之后制动、参考反向返回入口。由于目标未要求膝屈曲到新的构型，不能称为有效收腿。高度tuck_traj_虽然终点写0.66m，真正四关节命令来自normal_flight_joint_traj_；不能只看高度曲线判断收腿。

## 2. 起终边界、公式与保护

plan_tuck_round_trip（3910–3942）和begin_tuck（4110–4145）使用相同的目标构造。数组顺序HL/KL/HR/KR：

```text
q0 = {hip_pos_left_, knee_pos_left_, hip_pos_right_, knee_pos_right_}
v0 = {hip_vel_left_, knee_vel_left_, hip_vel_right_, knee_vel_right_}
tuck_comp = clamp(pitch_ - balance_offset_, -0.24, 0.24)
tuck_ik = inverse_kinematics_with_target_x(L_RETRACT_, tuck_comp, 0.0)
bounded_i = q0_i + clamp(ik_i - q0_i, -delta_i, +delta_i)
delta_i = hip:0.14rad / knee:0.04rad
qf_i = q0_i if abs(v0_i)>0.50 and (bounded_i-q0_i)*v0_i<0
       otherwise bounded_i
traj_i.init(now_sec, flight_round_trip_plan_.tuck_duration,
            q0_i, v0_i, 0.0, qf_i, 0.0, 0.0)
```

reaction_safe_configuration_step定义在flight_trajectory.hpp:20–36。实际正髋速、负膝速均超过0.50rad/s；缩腿所需髋角减小、膝角增大都逆着入速，所以四终点qf=q0。两处规划/执行一致，不能只改执行处而保持规划预检不变。

QuinticTrajectory（flight_trajectory.hpp:45–92）令u=clamp((t−t0)/T,0,1)，初/末加速度及末速度为0时：

```text
s(u)=10u³−15u⁴+6u⁵
h(u)=u−6u³+8u⁴−3u⁵
q=q0+v0*T*h+(qf−q0)*s
dq=v0*(1−18u²+32u³−15u⁴)+(qf−q0)*(30u²−60u³+30u⁴)/T
ddq=v0*(−36u+96u²−60u³)/T+(qf−q0)*(60u−180u²+120u³)/T²
```

本组T=0.060s，qf=q0、vf=af=a0=0；起速度为实测而非0。实际阶段60ms。

## 3. 原生髋轮轴距

由实际URDF joint origin/axis和每物理步原生q计算D=||R_x(qh)*origin_knee+R_x(qh+qk)*origin_wheel||，与原生link位姿直接算距离交叉核对，最大误差<1e−14m。左侧固定X偏移0.0500m，右侧−0.1072m，所以同一个平面腿长在左右对应不同三维轴距；报告不混用两者。髋角只整体旋转该向量，不能改变其模长；净缩短需要改变膝相对角。

## 4. 可行范围：不是调参扫描

解析五次式对固定60ms终点qf是线性约束。先按源准入257节点求qf区间交集，再用多项式导数实根检查并收紧连续时间q/dq/ddq极值；通过单调IK边界求根得到高度候选范围，没有试跑扫描幅度。沿用实际参数：hip速度11、加速度450、配置位置1.52；knee速度13、加速度500、配置位置1.5708，实际URDF硬位置±1.57另行收紧；URDF速度30和effort150不是替代当前飞行限制。所有限值未变。

|---|---|---|---:|
|B1|0.678759～0.689240（严格缩短时上端开）|358.2/664.2|75|

上述区间是**忽略反向保护和当前每关节步幅、仅看运动学限值**的宽松候选界，不是实际可执行范围，更不是制动/执行能力资格。三个区间没有共同固定target_z（B2下界0.691182高于B1/B3上界），所以不能随意预设一个统一绝对目标就宣称60ms都可达。若保留0.14/0.04步幅会进一步收窄；若保留反向保护，则在这批入口速度下有效缩腿终点集合为空。状态自适应腿长目标即使避开绝对高度差异，也不能绕过该方向保护。

目标qf本身在关节限位内，0.66目标的峰速也未超过11/13，但膝加速度超限，故不是IK无解，也不能靠放宽限制通过。当前qf=q0参考膝峰加速度约360–414rad/s²；实际执行输入髋峰约2.1–3.4Nm、膝约14.5–17.7Nm，低于飞行75/60Nm限幅（effort_allocation.hpp:13–16），但已有约0.15–0.18rad膝跟踪误差。该窗口包括入口命令交接；不能从“不饱和”推出执行器能准确完成新的反向轨迹。新动作需要的实际力矩、跟踪和接触证据仍未验证。

这只说明**总弹道时间不必然禁止有效收腿**。部署时间按原planner的零端速五次极值公式1.875*abs(Δq)/v_limit及sqrt((10/sqrt(3))*abs(Δq)/a_limit)求下限，至少0.090s；目标取同次历史landing_target_x，非新动作下重新测得的落脚目标。历史真实首触时刻也会随新构型/姿态变化，表格不是新的安全部署承诺。原实际EXTEND还有约0.298–0.310s至首触；延长TUCK会改变tuck_finished实际时刻及EXTEND采样边界，不能在本轮假装时机仍冻结。

TUCK→EXTEND仍以收到的实测q/v重新初始化（cpp4377–4420、3988–4010），并非从旧TUCK参考连续接续。当前膝参考位置跳变−0.146～−0.184rad。固定旧实测状态作敏感性比较，若旧TUCK终点直接换成未保护0.66 IK，膝新参考跳变会约为−0.349/−0.410/−0.342rad；但这不是新动作的真实预测，因为实际跟踪也会改变。它说明不能保证目标修改不放大既有参考断点。原始实际值和速度跳变完整保留。

角动量风险也不能忽略：有效收腿要求髋/膝逆着残余速度运动，髋变化可能增强机身后转，膝变化可能提供相反补偿，必须通过完整H=I_locked*omega_body+H_relative核账，不能只看某一个关节。此前[原生角动量诊断](../angular_momentum_20261007/REVIEW.md)已定量证明双髋/双膝贡献可大幅相互抵消；那些数值不能转用作新收腿轨迹的性能预测。本轮目标被保护全部挡住，没有合格候选可做新角动量因果验证，不伪造新的净姿态收益或执行能力。

## 6. 停止决定与保留

**不实施修改、不进行A/B。** 只改L_RETRACT_或一个新腿长数值不会改变实际关节终点；真正收腿至少需要重新处理反向运动保护与目标构造，并使规划/执行两处一致，还需闭合实际跟踪、参考衔接和角动量风险。是否需要重构多个阶段目前尚不能认定，但已无法作为仅改一个目标值且其他逻辑/时机冻结的实验。按授权边界停止，不擅自进行该设计。
