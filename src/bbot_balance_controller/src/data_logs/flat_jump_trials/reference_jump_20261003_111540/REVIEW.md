# 本轮复盘：独立开源参考候选

结论：完成独立文件、构建、测试和三次正常速度实跑，候选不通过落地验收，不提升为默认。恢复版原文件及原二进制、MPC工作均保留。

源程序采用有限推膝力矩，速度退出和顶点展腿；BBOT保持自己的CAD坐标、质量、扭矩预算、接触确认、ROS启动与平衡闭环。两者的参数不能互换。

## 观察与推论

1. 第一、二次在离地边界膝触及−1.57rad，紧接着出现明显后仰。第二次仍在q=−0.942、v=−21.30rad/s收到净膝命令−46.44Nm；到q=−1.055才转为+14.07Nm，已没有足够制动行程。只缩短速度预瞄不能覆盖停止距离。
2. 第三次提前卸力后，THRUST/FLIGHT膝角最小值−1.49322rad，避开硬限位；正常子相位为ARREST→TUCK→EXTEND，控制器确认离地时pitch=+0.066rad、rate=−0.018rad/s。
3. 第三次收腿末尾（9.258s），实测髋0.780rad对目标0.497rad、实测膝−0.814rad对目标−0.640rad。收腿段最大膝跟踪误差0.548rad。名义高度不能当实际姿态。
4. 展腿结束前（9.523s）机身pitch=−0.506rad（约−29°），rate=−1.344rad/s。随后非轮碰撞、EMERGENCY，没有BALANCE恢复。全程审计FAIL。可以确认当前控制组合没有解决后仰；不能只凭这些曲线认定唯一根因是某一关节力矩。
5. `actual_tau_knee_left`逐行等于`knee_cmd_left`，JointState effort全0。本轮只能分析命令与实际关节运动/IMU响应，不能证明真实执行力矩波形。
