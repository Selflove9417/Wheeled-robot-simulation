# 平地跳跃命令时序配对试验（2026-09-26）

目标：区分 `/jump_cmd` 命令行发送的启动抖动与控制器内部阶段的波动。仅增加时间戳、事件快照和分析脚本；未修改跳跃增益、落地控制或自适应平衡控制。

## 方法与结果

- 同一版本、默认跳跃参数，按 CLI→常驻、CLI→常驻、CLI→常驻运行 3 组配对。命令前状态与采样龄均符合预设匹配带；6 次均形成有效飞行，但 **0/6 完整落地恢复**。
- 从发送动作开始到控制器收到命令：CLI 为 **745–1246 ms**，常驻为 **0 ms（仿真时钟记录分辨率内）**。该值包括 CLI 进程启动，不能解释为纯通信时延。
- 命令前快照到首次 PRE_JUMP 行：CLI 为 **755–1255 ms**，常驻均为 **10 ms**。控制器收到→接受均为 0 ms（记录分辨率内），接受→首行约 1–5 ms。
- PRE_JUMP 左轮速的组内极差：CLI **0.138 rad/s**，常驻 **0.022 rad/s**；说明去除外部发送抖动后，早期状态更一致。
- THRUST 左轮速极差却由 CLI 的 **0.033 rad/s** 变为常驻的 **2.005 rad/s**；FLIGHT 左轮速极差分别为 **2.46** 与 **2.22 rad/s**。因此后续状态离散和落地失败不能仅归因于命令发送抖动，也不能声称常驻发送改善了落地。

## 续查：控制周期与下蹲分叉

- 三次常驻发送试验的 SQUAT 首行状态接近；约 0.10 s 时左轮速为 -5.05、-5.12、-5.07 rad/s。第二次在约 0.19 s 后明显分叉，THRUST 入口轮速为 -7.26 rad/s，另两次为 -5.27、-5.25 rad/s。
- 第二次常驻试验的 SQUAT 日志有 **19 个 10 ms 间隔**，另两次均为 5 ms 连续记录（各 0 个 10 ms 间隔）；首次 10 ms 间隔出现于 SQUAT 起点后 0.025 s。其关节采样时间戳跨间隔继续前进，且 SQUAT 每次有效控制循环都会写一行，故这些间隔代表控制循环未在每个 5 ms 仿真步执行，而非单纯 CSV 抽样。
- 同一次试验 PRE_JUMP、THRUST、FLIGHT 也分别有 35、7、6 个 10 ms 间隔。控制器用 5 ms 墙钟定时器、仿真时钟决定控制是否执行；现有日志无法分辨是调度负载、时钟发布节奏还是别的原因。
- 第三次常驻试验 SQUAT 没有 10 ms 间隔，FLIGHT 轮腿速度仍与第一次不同。因此周期缺步是已观察到的**候选放大因素**，不是全部波动或落地失败的已证实根因。

## 2026-09-27 节拍复测与推地门控

- 在控制日志末尾追加 `control_sim_dt_ms`、`control_wall_dt_ms` 和 `timer_calls_since_control` 三项只读诊断；默认参数、常驻发令复测 3 次，**3/3 有效飞行、0/3 落地恢复**。
- 约 10 ms 的有效控制间隔对应约 10 ms 墙钟间隔，期间通常记录到 2 次定时回调。可排除“定时器完全没有回调”的简单解释；仍需区分仿真时钟发布与回调读取的先后。三次 THRUST 阶段分别有 0、2、0 个 10 ms 间隔，不能用 THRUST 缺步单独解释三次飞行入口差异。
- 三次 THRUST 入口状态接近，但初始姿态门控打开时间为 **15、45、45 ms**。后两次约在 20 ms 处俯仰角速度误差达到 **0.182 rad/s**，仅略高于 **0.18 rad/s** 门限，连续稳定计数清零；第一次在开门前的连续确认采样均位于门限内。
- 与门控分叉一致，速度锁存出现在 THRUST 后 **165、190、190 ms**，进入 FLIGHT 为 **251、275、276 ms**。这是代码门控与观测时序一致的机制线索；尚不能证明角速度微差的来源，也不能据此推断放宽门限会改善落地。
- 下一轮若要改控制，应预先定义门控鲁棒性候选及配对验收条件，再单变量试验；本轮仅完成观测，不修改门限、推力或落地参数。

## 决定与边界

- 预设的 3 组有效配对、命令时序及 PRE_JUMP 轮速收敛判据已满足：**仅将可重复性观测模式默认改为常驻发送**；普通试验默认仍为 CLI，可用 `--command-transport cli` 在观测模式显式复测旧路径。
- 后续优先在常驻发送的同一入口下验证 THRUST 初始姿态门控的鲁棒性，再研究落地恢复；本轮不调控制参数。
