# velocity 接管与卸力保护验证 · 2026-10-06

**跳跃修复验收 FAIL。本轮 1 次实跑，0 次腾空，0 次修复成功。** 实时倍率 1.0、物理步长 1 ms；没有更改动作速度、飞行限速、扭矩上限或验收门槛。默认 README velocity、完整跳跃演示和 MPC 未改动。

本轮处理前一候选的两个直接问题：推地参考单帧无效后切回旧控制造成跳变，以及没有实际制动依据却让膝接近机械限位。跳高和落地后退尚未改善。

## 已实现并运行的改动

- 独立实验控制器缓存 IMU 与关节样本，按相同原始时间戳配对，要求有限值且不超过 20 ms；较新的未配对回调不会抹掉已有的新鲜配对。
- 推地门打开并接管后，控制来源保持到 THRUST 结束。逆解拒绝、旧数据、失去支撑、制动行程不足等情况锁定卸力/阻尼，不再切回旧 PD/前馈，也不再重新推进。
- 制动行程使用实际 q/v：`|v| * 总延迟 + v² / (2 * 实际制动减速度) + 0.010 rad`，与现有软限位剩余行程比较。参考速度变化率不作为物理刹停能力。没有合格减速度则标记检查无效，并拒绝继续推进。
- 卸力阶段支撑推进力为 0，髋采用已有上限内的单一速度反馈，膝采用单一 `-3*v` 阻尼，避免推进项抵消制动。保留原接触、新鲜度、姿态、腿长与恢复保护。
- `.capture_control.csv` 保留接管阶段、拒绝原因、配对时间、有效标志、实际状态、目标/执行参考、行程、力矩和推进力；`.command_publication.csv` 保留发布与控制时刻。
- 辅助扭矩记录器改用未占用的输出前缀，在发跳跃命令前检查进程和反馈。此次得到 2612 行发布命令、18516 行关节反馈。

飞行收腿/首触目标保持上一候选的 0.60 m，本轮没有新增轨迹调参。分配器关闭；原生只读观测器沿用现有版本，未创建或修改 JointForceCmd。

## 验证范围与剩余工作

独立构建成功；`velocity_launch_capture` 测试通过，Release 下断言保持启用。测试覆盖回调顺序、配对新鲜度、时钟回退、制动行程计算、无制动证据、接管锁定和拒绝后不重新推进。它们验证软件逻辑，不验证物理制动能力。

56 条旧 THRUST 状态的逻辑回放在 6.814 s 首次接管时锁定卸力，比旧记录中 7.067 s 碰限位早 253 ms。这个时间差只来自旧状态回放，不是新轨迹的停止位置预测，也不是一次跳跃。

对两个已有实跑记录按有效物理输入、接地、远离限位、高速向限位运动、反向命令筛选，膝没有合格制动样本；髋施加反向命令也不总能减速。没有据此编造正的减速度下界。参数默认 0 表示未合格，不能用 450/500 rad/s² 的参考限速代替。

下一步先在远离限位、接地且姿态受保护的受限制动试验中取得实际髋/膝减速与命令延迟；完整输入响应核对通过后再启用有界 P 轮速分配器。真实离地 q/v/H 和收腿/首触验证仍在其后。当前实验入口会在证据不足时退出恢复，不能替换默认。
